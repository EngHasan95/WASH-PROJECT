# تجربة Windows دون تثبيت على نظام التشغيل

طلب المستخدم نسخة تعمل مباشرة على جهاز Windows التابع لجهة العمل، دون Rancher أو Docker أو WSL أو آلة افتراضية. أُضيفت طريقة تشغيل مستقلة دون تغيير نوع قاعدة البيانات. ثم أذن بإصلاح النواقص التطبيقية والتشغيلية؛ راجع [تقرير الإصلاحات الحالي](review-fixes-2026-10-07-ar.md).

## الحزمة وطريقة الاستخدام

الحزمة: `test-results/wash-windows-portable.zip`. فكّها في مجلد محلي قابل للكتابة على NTFS، مثل `WASH-Demo` داخل المستندات، ثم شغّل `Start.cmd` بحساب Windows المعتاد. يفتح دليل اللجنة في المتصفح الحالي. تبقى نافذة Start مفتوحة. الإيقاف بـ`Stop.cmd` أو Ctrl+C، والنسخ الاحتياطي بـ`Backup.cmd` أثناء التشغيل. ينتظر Stop انتهاء قاعدة البيانات وتحرير قفل التشغيل قبل تأكيد الإيقاف، ويستطيع إيقاف قاعدة هذه النسخة بعد فقد المشغّل بشرط التحقق من ملكيتها. الدليل العربي المستقل هو `README.html` داخل الحزمة.

المستهدف Windows 10/11 x64. تتضمن الحزمة Python 3.13.16 المضمن الرسمي، PostgreSQL 17.11 بأرشيف EDB الرسمي، المكتبات ذات إصدارات التطبيق نفسها، Waitress 3.0.2 لخدمة WSGI على Windows، ومكتبات Microsoft C++ اللازمة بجانب PostgreSQL. لا يُثبت AppX أو برنامج Microsoft أو خدمة PostgreSQL، ولا تُعدّل إعدادات Windows أو السجل أو PATH العام أو الجدار الناري. جميع متغيرات الإعداد مؤقتة داخل عمليات النسخة فقط. بعد فك الحزمة لا يحتاج التشغيل لتنزيل متطلبات أو اتصال بالإنترنت.

تنشأ الإعدادات والمفتاح وقاعدة البيانات والصور ونسخ البيانات في `data/` داخل مجلد الحزمة. تضبط DACL للمجلد لحساب Windows الحالي وSYSTEM فقط مع توريثها للمجلدات الجديدة. يلزم NTFS؛ يرفض المشغّل مجلد البيانات المعاد توجيهه أو قرصًا لا يدعم الحماية المطلوبة. لا تُشارك الإعدادات أو تحذفها: فقدانها مع وجود قاعدة يجعل Start يرفض إنشاء كلمة مرور بديلة. إيقاف وإعادة التشغيل يحافظان على البيانات وعلى منفذ المتصفح المرتبط بمخازن offline. التشغيل الثاني يفتح النسخة نفسها بدل تشغيل قاعدة جديدة.

## النسخ الكاملة والاستعادة الآمنة

يحتوي كل مجلد مكتمل في `data/backups/wash-*` على قاعدة البيانات والصور و`metadata/` وفيه إعداد المنافذ وكلمة مرور القاعدة وملف حسابات اللجنة ومفتاح Django. هذه ملفات خاصة محمية بصلاحيات مجلد data، وليست مشفرة. لا تُرسلها في المحادثة ولا تضفها إلى Git أو ZIP التوزيع العام. تُحتفظ بأحدث سبع لقطات مكتملة ومتحقق منها فقط؛ لا يُحذف أي مجلد ناقص أو غير معروف تلقائيًا. يلزم احتياطي مساحة256MiB إضافة إلى تقدير مساحة التفريغ والصور؛ نقص المساحة يفشل النسخ بتنبيه دون حذف قاعدة البيانات. يظهر فشل النسخ في نافذة Start، وفي `data/backup.log` و`data/backup-health.json`.

للاستعادة: أوقف النسخة القديمة تمامًا، وفك حزمة جديدة في مجلد آخر **دون تشغيل Start أولًا**، ثم شغّل `Restore.cmd` فيها وأدخل مسار مجلد لقطة مكتملة. تُفحص بصمات القاعدة والصور والإعدادات قبل البدء، ويُرفض الاستبدال أمام أي data قائمة. تُستعاد منافذ النسخة الأصلية للحفاظ على صلة مسودات المتصفح دون اتصال؛ إذا كانت المنافذ مشغولة تُرفض العملية بدل تغييرها بصمت. بعد نجاح Restore شغّل Start. لا تُحذف النسخة القديمة أو اللقطة الأصلية. أي استعادة فاشلة تترك علامة واضحة ويُرفض تشغيل البيانات الجزئية؛ احتفظ بها للتشخيص وأعد الاستعادة إلى مجلد نظيف آخر.

اللقطات القديمة ذات الملفات الثلاثة فقط ليست استعادة محمولة كاملة؛ احتفظ بها للاستعادة التقنية ولا تُعتبر مفقودة. انسخ مجلد لقطة مكتملة إلى وسيط ثانٍ محمي لحمايته من فقد القرص؛ بقاؤه على قرص النظام نفسه لا يكفي. حماية NTFS لا تعوّض التشفير عندما تنقل النسخ إلى وسيط مشترك أو غير موثوق.

يُستأنف إعداد قاعدة أكمل initdb لكنه انقطع قبل ضبط المنفذ. يراجع المشغّل الإعداد والمنفذ قبل إطلاق PostgreSQL، ويرفض العنقود الذي انقطع أثناء initdb نفسه دون حذفه. تلف علامة جدولة النسخ لا يمنع تشغيل النظام؛ تُعاد جدولة لقطة جديدة مع تنبيه.

## حدود الوصول

الخادم وقاعدة البيانات يستمعان على `127.0.0.1` فقط، بأرقام منافذ منفصلة محفوظة في الإعدادات المحلية. يستخدم PostgreSQL مصادقة SCRAM بكلمة مرور عشوائية محلية. يدخل المستخدم عبر أزرار اللجنة الخيالية نفسها؛ إعدادات اللجنة وضوابط Host وCSRF وهوياتها غير القابلة للدخول بكلمة مرور محفوظة دون تغيير. لا تستخدم هذه النسخة لبيانات مؤسسية حقيقية أو للنشر العام. الهاتف لا يستطيع الاتصال بخادم محصور على كمبيوتر آخر؛ اختبار الهاتف عبر الإنترنت يحتاج نشر HTTPS مستقلًا بالحسابات الفعلية دون أزرار التجربة.

## الفصل بين التطبيق وطريقة التشغيل

يقع التطبيق في `app/` داخل الحزمة. يتأكد الفحص من تطابق `config/` و`portal/` و`templates/` و`static/` مع المصدر الحالي بايتًا ببايت؛ لا يغيّر التغليف وظائف التطبيق. يبقى المصدر الحالي متضمنًا الإصلاحات المأذون بها، مع PostgreSQL ومعاملاتها وقفل صفوفها لضمان سلوك المالية والإغلاق.

`portable_windows/settings.py` يورث إعدادات اللجنة الأصلية ويبدّل فقط مسار وسيط القفل. `locking.py` يستخدم `LockFileEx` المشترك والحصري على Windows وfcntl على Linux للتحقق. `runner.py` يستخدم محوّل القفل و`snapshots.py` للنسخ المحمولة الكاملة، ويبقي سكريبت التحقق الأصلي للاستعادة المؤقتة دون تغيير. يحافظ القفل على إيقاف الطلبات أثناء اللقطة الحصرية، مع الاستجابة503 نفسها عند الانتظار. `launcher.py` يشرف على العمليات، والتجهيز مرة واحدة، والنسخ التلقائي كل24 ساعة أثناء التشغيل، والإيقاف المرتبط برمز خاص محلي؛ لا يستخدم إيقافًا عشوائيًا بمعرّف عملية أو حذف قاعدة.

هذه الوثيقة تصف تشغيل النسخة المحمولة. نتائج إصلاح وظائف التطبيق موثقة في تقارير المرحلة الحالية، ولا يُستدل من اختبار المشغّل وحده على اكتمالها.

## التحقق المنفذ وحدوده

- اجتازت138 اختبارات Django بعد الإصلاحات الحالية.
- اجتاز المشغّل نفسه وWaitress في Linux بقاعدة PostgreSQL مستقلة: التشغيل الأول، النسخ التلقائي، تشغيل Start ثانية، الإيقاف وإعادة التشغيل، حفظ الإعدادات، رفض الإعدادات المفقودة مع قاعدة محتفظة، ورفض تعديل ملف الحزمة قبل تشغيل القاعدة. استخدم الاختبار مسارًا يحتوي مسافات ولم يغيّر قاعدة التطوير أو قاعدة Docker القائمة.
- أعيد استخدام ست مجموعات اختبار المتصفح الأصلية على المشغّل المحمول: تبديل الأدوار وتخطيط الهاتف، توقف الخادم الفعلي وحفظ البلاغ وإعادة فتحه والمزامنة مرة واحدة، كامل معالجة البلاغ، إحالات المخالفة واعتماد المالية وإغلاق المدير، المذكرة والنموذج والتقرير وPDF، واستبعاد الصفحات الخاصة من CacheStorage.
- اجتاز النسخ الاحتياطي اليدوي استعادة إلى قاعدة جديدة مؤقتة، بما فيها المستند الصادر والمرفق المرجعي. واجتاز اختبار القفل عبر عمليات مستقلة واستجابة503 للطلب أثناء اللقطة الحصرية.
- روجعت معماريات PE واعتماديات DLL للملفات المضمّنة وبصمات الملفات، وتطابق المحتوى الأصلي وعدم تضمين قاعدة بيانات أو إعدادات أو مفاتيح أو مرفقات تشغيلية.

أُعيد الاختبار الكامل بعد الإصلاحات، مع الإسناد المالي ونتائج التنفيذ وصورها. تُحفظ النتائج وبصمات المصدر في `validation-results.json` داخل الحزمة. لا يحوّل نجاح التشغيل في Linux الاختبار الأصلي على Windows إلى اختبار منفذ.

**لم يُشغّل إصدار Windows الأصلي فعليًا على جهاز Windows في هذه البيئة Linux.** لذلك يبقى تشغيل ملفاتexe وDLL وواجهات DACL وLockFileEx على Windows اختبارًا مطلوبًا عند أول تجربة المستخدم. لم تُختبر ARM أو Windows32بت أو سياسات حماية جهاز المؤسسة. لا تُعطل حماية الجهة أو تتجاوز منعها للبرامج المحمولة.

## إعادة البناء في السحابة

1. من جذر المشروع، شغّل `bash scripts/setup.sh`، وثبّت Waitress3.0.2 وtzdata2026.5 في `.venv` لاختبار المشغّل. تُضمّن بيانات المنطقة الزمنية لأن Windows لا يقدم قاعدة IANA التي يعتمد عليها توقيت عدن في Django.
2. نزّل المكتبات المحددة في `portable_windows/requirements.txt` إلى `.local/windows-portable-wheels` باستخدام pip download مع `--platform win_amd64 --python-version 313 --implementation cp --abi cp313 --only-binary=:all:`. لا تستخدم مكتبات Linux داخل حزمة Windows.
3. شغّل `python3 scripts/windows_portable_regression_checks.py`، ثم `python3 scripts/windows_portable_checks.py`. يستخدم Playwright الموجود على النظام وPython/Django الموجودين في `.venv` وPostgreSQL المحلي؛ ينشئ ويحذف عنقود الاختبار الخاص فقط.
4. شغّل `.venv/bin/python scripts/package_windows_portable.py`. ينزّل أرشيفات المصادر الرسمية عند فقدانها ويتحقق من البصمات المقيدة، ومن بصمات PyPI وAppxBlockMap، ويجمع المصدر المسموح وملف المذكرة المرجعية فقط. لا تُعطّل TLS أو فحوص البصمات عند فشل التحميل.
5. افحص `package-manifest.json` داخل الناتج وملفSHA256 بجانبه. لا يُعاد البناء فوق مجلد نسخة محمولة بدأ التشغيل فيه وأنشأ `data/`.

تُحفظ مصادر التنزيل وبصماتها في بيان الحزمة: Python ببصمة SPDX الرسمية، PostgreSQL ببصمة مثبتة للأرشيف المتلقى عبر HTTPS الرسمي، Microsoft ببصمة الأرشيف والتحقق من كتله، والمكتبات ببصمات PyPI. لا تُدّعى مصادقة Authenticode أصلية على Windows من اختبار Linux. الشبكة تحتاج النطاقات الرسمية التي أُضيفت إلى مسودة إعداد البيئة؛ حفظ الإعداد لا يثبت نشر لقطة جديدة أو استعادتها في مهمة جديدة.

## إصلاحات التعافي — 7 أكتوبر 2026

عولجت عيوب المشغّل المثبتة في `review-windows-portable-2026-10-06-ar.md`. يشمل `scripts/windows_portable_regression_checks.py` الآن اختبارات مستقلة في مجلدات وعناقيد Linux خاصة، منها مسار عربي ومسافات:

- اكتمال الملفات الخاصة اللازمة للاستعادة وتطابقها مع الأصل.
- الاحتفاظ بسبع لقطات كاملة ومتحقق منها، ورفض نقص المساحة قبل التفريغ.
- استمرار التشغيل وإصلاح الجدولة أمام أربع قيم تالفة للوقت وJSON.
- إيقاف PostgreSQL بعد قتل المشغّل قسرًا ومع تلف ملف التحكم، بعد تحقق ملكية مجلد القاعدة.
- عدم إعلان Stop نجاحًا كاذبًا إذا فُقد settings أمام قاعدة قائمة.
- انتظار إيقاف قاعدة أُبطئ إيقافها3ثوانٍ في محوّل الاختبار، ثم نجاح إعادة التشغيل الفورية.
- إعادة تطبيق إعداد المنفذ بعد initdb مكتمل، ورفض منفذ مشغول قبل إطلاق قاعدة جديدة.
- استعادة لقطة كاملة إلى مجلد نظيف، وتطابق إعدادات اللجنة والمفتاح والمرفق الخيالي، ثم تشغيلها بنجاح.
- رفض الاستعادة فوق بيانات موجودة، ورفض لقطة تالف ملف metadata فيها قبل إنشاء settings.
- تجاوز أربعة أشكال JSON تالفة في اللقطات القديمة دون إفشال النسخة الجديدة أو إعادة النسخ كل30ثانية، مع إبقاء الملفات التالفة دون حذف.
- رفض بيان نسخ ليس JSON object أو خريطة ملفات null أو إعدادات خاطئة البنية برسالة واضحة، وتجاوز أربع لقطات قديمة تالفة البنية أثناء النسخ والاحتفاظ دون حذفها أو تحويل اللقطة الجديدة إلى فشل. يختبر السيناريو نفسه إصلاح علامة النسخ التلقائي رغم وجود تلك الملفات القديمة.

اجتازت هذه الاختبارات بالمصدر الحالي. تحفظ نتيجتها وبصمات المشغّل في `test-results/windows-portable-validation/regressions.json`. يحتاج فحص المسارات الستة الأصلي التالي إلى النتيجة نفسها قبل إعادة تعبئة ZIP؛ لا يُعتبر ZIP السابق مصححًا بمجرد تعديل ملفات المصدر. هذه الاختبارات لا تنفذ exe أو DACL أو LockFileEx على Windows؛ يظل الاختبار الأصلي مطلوبًا.
