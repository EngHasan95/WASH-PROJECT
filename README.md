# بوابة المياه — مأرب

نظام عربي لإدارة بلاغات المستفيدين والمخالفات الميدانية للمؤسسة العامة للمياه والصرف الصحي — فرع مأرب.

## حالة التنفيذ

أُصلحت النواقص المثبتة في مراجعات 6 أكتوبر، بما فيها نتائج التنفيذ وصورها دون اتصال، والإسناد وإعادة الإسناد، وإدارة الموظفين وحماية الدخول، وفلاتر التقارير، والتعافي والنسخ والاستعادة. [تفاصيل الإصلاحات والتحقق وحدوده](docs/review-fixes-2026-10-07-ar.md).

تشمل النسخة الحالية حسابات المستفيدين والموظفين، وتسجيل بلاغ المستفيد وصوره وحفظه المحلي ومزامنته، وسجلات البحث والمتابعة الخاصة. يوجه النظام البلاغ إلى الشؤون الفنية أو المالية بحسب نوعه. يسند المدير الفني البلاغ الفني، ويسجل المنفذ النتيجة، ويغلق المدير البلاغ أو يعيده للمعالجة. نافذة مستقلة تسجل مخالفات الفنيين حتى أثناء الانقطاع، ثم تدير إحالات مسؤول النظام والسكرتارية والمتابعة وعودة النتائج للفنية والمالية. [تفاصيل المسارين وحدودهما](docs/stage-4-5-ar.md).

تعرض لوحة المدير الفني أعداد البلاغات والمخالفات وتوزيعها على الأقسام والفنيين. تعتمد المالية رسوم المخالفة وفق المذكرة المرفقة وتؤكد سند السداد، ثم يغلق المدير الفني الملف بعد توثيق المعالجة. [تفاصيل الرسوم وحدود المذكرة](docs/requirements/violation-fees-ar.md). تُحرر السكرتارية محاضر ومذكرات داخل الملف، وتصدر نسخًا محفوظة للطباعة والتوقيع والختم. توجد نسخ احتياطية منسقة مع طلبات النظام، وجدولة محلية أثناء تشغيل بيئة التطوير، وقالب مؤقت يومي لتشغيل المؤسسة. حفظ النسخ خارج الخادم يحتاج وجهة المؤسسة عند النشر. لم يُنشر النظام عامًا. عند الانقطاع يعرض سجل المستفيد نسخ بلاغات حسابه المحفوظة على الجهاز نفسه؛ الحالة الحالية والسجل الكامل والسجل الداخلي تحتاج الاتصال.

لا تحتاج بيئة التطوير الحالية إلى أي حساب لخدمة خارجية أو اشتراك. لم ينشر النظام على استضافة عامة. إذا اعتمدته المؤسسة، تتولى ترتيبات وتكاليف النسخة التشغيلية.

تتيح «مكتبة النماذج» إضافة أشكال تقارير جديدة وتعديل ترويساتها ونصوصها وجداولها وحقولها الإضافية. يمكن استيراد نص DOCX ثم ضبط الشكل ومعاينته. يعتمد المدير الفني الإصدار ليظهر في تقارير البلاغ أو المخالفة أو الإدارة؛ تبقى التقارير المحفوظة ثابتة عند تعديل النموذج أو الملف. [طريقة إضافة نموذج](docs/report-templates-ar.md).

## إعداد المطور

على بيئة Debian 13 الحالية، ومن جذر المستودع:

```bash
bash scripts/setup.sh
bash scripts/start.sh
```

يهيئ الإعداد بيئة Python معزولة وPostgreSQL محليًا داخل `.local/` دون صلاحيات root. الاتصال بقاعدة التطوير عبر Unix socket خاص فقط، دون فتح منفذ شبكة لقاعدة البيانات. أوامر الإعداد قابلة للتكرار ولا تحذف البيانات.

إنشاء أول مدير فني، عند تجهيز الحسابات الفعلية، يتم بأمر يطلب كلمة المرور سرًا ولا يقبلها ضمن سطر الأمر:

```bash
.venv/bin/python manage.py bootstrap_director --username director --name 'مدير الشؤون الفنية'
```

لا توجد كلمات مرور ثابتة أو حسابات فعلية جاهزة في المصدر. حسابات اختبارات المتصفح مؤقتة وتحذف بعد الاختبار.

## التحقق

```bash
.venv/bin/python manage.py test portal
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py check
python3 scripts/browser_checks.py
python3 scripts/violation_browser_checks.py
python3 scripts/template_browser_checks.py
.venv/bin/python scripts/operations_checks.py
```

لإنشاء نسخة يدوية في وجهة خاصة ومستقلة:

```bash
.venv/bin/python scripts/backup.py /path/to/separate/backup-volume
```

يضم المجلد الناتج نسخة PostgreSQL بصيغة custom، وأرشيف الصور الخاصة، وبصمات SHA-256. يتوقف قبول طلبات التطبيق مؤقتًا أثناء النسخ لضمان تطابق قاعدة البيانات والملفات على الخادم الواحد. اختُبرت استعادة قاعدة تجريبية ومستند ومرفق خاص من النسخة، ورفض أرشيف معدل. يختبر `scripts/verify_backup.py` الاستعادة في قاعدة مؤقتة جديدة ولا يستبدل قاعدة التشغيل. يلزم ترتيب وجهة دائمة خارج الخادم قبل تشغيل المؤسسة. لا تحفظ النسخ داخل Git.

اختبارات المتصفح تستخدم Playwright وChromium الموجودين في بيئة Codex، وتشغل خادم اختبار مستقلًا وتوقفه للتحقق من الانقطاع الحقيقي. تفحص العمل دون اتصال وإعادة فتح المتصفح والمزامنة وعدم التكرار وفصل الحسابات. تفحص أيضًا البلاغ الكامل وصوره وترقية التخزين المحلي وضياع رد الاستلام، والسجل والبحث والتفاصيل الخاصة والتصفح بين الصفحات والنسخ المحلية عند الانقطاع. تكتب صورًا في `test-results/` المجلد المستثنى من Git. لا تطبع أو تحفظ كلمات مرور الاختبار.

العمل دون اتصال يحتاج زيارة أولى بوجود إنترنت وHTTPS عند النشر. افتح النظام عند الوصول إلى الإنترنت لتتم المزامنة؛ لا يضمن كل متصفح المزامنة وهو مغلق. حذف بيانات المتصفح قد يفقد البيانات والصور المحلية غير المرسلة.

## نقل النظام إلى التشغيل

الطريقة الحالية للتجربة على Windows 10/11 x64 هي [الحزمة المحمولة](docs/windows-portable-ar.md)، دون Docker أو WSL أو آلة افتراضية أو تثبيت متطلبات على النظام. فكّ `test-results/wash-windows-portable.zip` في مجلد قابل للكتابة على NTFS، ثم شغّل `Start.cmd`. تستخدم `Stop.cmd` للإيقاف و`Backup.cmd` للنسخ، و`Restore.cmd` لاستعادة لقطة كاملة إلى حزمة جديدة لم يبدأ تشغيلها. تحتوي الحزمة دليلًا عربيًا وحسابات لجنة خيالية، وتحافظ على نتائج التقييم بعد الإيقاف. اختُبر المشغّل في Linux وفُحصت ملفات Windows؛ تشغيل Windows الفعلي لم ينفذ في هذه البيئة.

تبقى [نسخة اللجنة السابقة بالحاويات](docs/committee-demo-ar.md) متاحة لمن لديه محرك حاويات Linux مسبقًا؛ تفاصيلها في `committee/README.html`. النسختان مستقلتان عن بيانات التطوير. البيئة الحالية لا تنشر رابطًا عامًا داخل ChatGPT.

يمكن استخدام PostgreSQL خارجيًا عبر `DATABASE_URL`. يتطلب التشغيل الإنتاجي `DJANGO_DEBUG=0` و`DJANGO_SECRET_KEY` و`DJANGO_ALLOWED_HOSTS`، وخادم تطبيق إنتاجيًا وHTTPS وتخزينًا خاصًا مستمرًا للمرفقات ونسخًا احتياطية مجربة. يمكن تحديد مجلد الصور عبر `WASH_MEDIA_ROOT`، ولا يخدم مباشرة عبر مسار ملفات عام. لا تستخدم خادم Django للتطوير كخادم إنتاجي. اختُبر التشغيل عبر Gunicorn مع إيقاف وضع التطوير، ورفض المضيف غير المعتمد وإعادة التوجيه إلى HTTPS. ملفات الخدمة والمؤقت وقالب وكيل HTTPS في `deploy/`؛ تعليمات تشغيل المؤسسة في [دليل التشغيل](docs/operations-ar.md). هذه حزمة تجهيز، وليست استضافة عامة مفعلة.
